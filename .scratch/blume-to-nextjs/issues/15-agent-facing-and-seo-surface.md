# Agent-facing and SEO surface

Type: grilling
Status: open
Blocked by: 02, 04

## Question

An entire agent-facing surface is live in production, generated by Blume
defaults and declared nowhere in `blume.config.ts`. Verified live:

| Endpoint | Status | Size |
| --- | --- | --- |
| `/llms.txt` | 200 `text/plain` | 9.3 KB |
| `/llms-full.txt` | 200 `text/plain` | 297 KB |
| `/docs/**/*.md` (per docs page) | 200 `text/markdown` | e.g. button 3.9 KB |
| `/index.md` | 200 `text/markdown` | 9.3 KB |
| `/sitemap.xml` | 200 `application/xml` | 5.7 KB |
| `/robots.txt` | 200 `text/plain` | 120 B |
| `/rss.xml`, MCP routes | 404 | not in use |

These are root URLs, so they are inside the frozen URL contract.
`/llms.txt` is structured with the site's own vocabulary (`## Docs`,
`## Primitives`) and its descriptions come from MDX frontmatter. `robots.txt`
carries `Content-Signal: search=yes, ai-input=yes, ai-train=yes` and a sitemap
reference.

Settle:

1. **Which of these are reproduced?** All of them is the default answer since
   the URLs are frozen, but say it explicitly per endpoint.
2. **Markdown serialization of custom components.** This is the real work.
   Measured from production: `<Component path="button/button-demo" />` becomes a
   fenced `tsx` block holding the demo's actual source — valuable, and worth
   keeping. But `<InstallCommand item="button" />` is emitted **verbatim as raw
   JSX**, so an agent reads the literal tag instead of
   `npx shadcn@latest add @sevenui/button`. That is a defect, not a contract:
   fix it. Decide the serializer for every component that survives
   `04-mdx-content-component-parity-set`, and record `<InstallCommand>` as a
   deliberate, spec-recorded improvement over parity.
3. **`/llms.txt` structure.** Its section grouping mirrors the sidebar. Does it
   read from the same nav source (`03-sidebar-and-nav-source-of-truth`), and
   does it gain the `/components` and `/blocks` surfaces, which it omits today?
4. **`/llms-full.txt` at 297 KB.** Reproduced as-is, or reconsidered? It is a
   concatenation of the corpus; its size and what it includes (demo sources
   dominate) is a choice worth making on purpose.
5. **Per-page `.md` routing.** `/docs/components/button.md` returns markdown
   while `/docs/index.md` 404s but `/index.md` 200s. Establish the exact rule
   Blume applies, then decide whether to reproduce it faithfully or normalize
   it — a 404 asymmetry may be an upstream quirk rather than a contract.
6. **`sitemap.xml` contents.** Which routes, and does it include `/blocks`
   category routes that now come from an ISR'd manifest (a sitemap generated at
   build time would miss newly added ones)?
7. **`robots.txt`** — reproduce the `Content-Signal` line verbatim, including
   the `ai-train=yes` stance, or revisit it? It is a policy statement, not a
   technical detail.
8. **Blume extras to check before assuming they are off.** `seo.structuredData`
   (JSON-LD), `seo.agentReadability` (default true — advertises the markdown
   endpoints for discovery, likely a `<link>` or header), the "Open in chat"
   page action (default true), and `webmcp` (default true — a client-side
   WebMCP island). Measure whether each is actually rendered in production
   before deciding it does not come along.
